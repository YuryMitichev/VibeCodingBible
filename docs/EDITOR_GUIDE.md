# Editor Guide

Version: 0.2.0
Status: Active

---

## 1. Назначение

Этот документ описывает рабочий процесс для авторов, редакторов и ИИ-инструментов, участвующих в написании **Vibe Coding Bible**.

Связанные документы:

- [STYLE_GUIDE.md](STYLE_GUIDE.md) — правила стиля и формата глав
- [TERMINOLOGY.md](TERMINOLOGY.md) — единая терминология
- [BOOK_OUTLINE.md](BOOK_OUTLINE.md) — структура книги
- [PROJECT_MANIFEST.md](PROJECT_MANIFEST.md) — принципы и стандарты проекта

---

## 2. Роли

| Роль | Ответственность |
|---|---|
| Project Owner | Стратегия, утверждение ключевых решений |
| Architect | Структура книги и репозитория |
| Technical Editor | Терминология, стиль, качество текста |
| Contributor | Написание и улучшение материалов |

---

## 3. Перед началом работы

1. Прочитайте [PROJECT_MANIFEST.md](PROJECT_MANIFEST.md) и [AI_CONTEXT.md](AI_CONTEXT.md).
2. Ознакомьтесь с [BOOK_OUTLINE.md](BOOK_OUTLINE.md) — определите место вашей главы в общей структуре.
3. Проверьте [PROJECT_STATE.md](PROJECT_STATE.md) — убедитесь, что глава не занята другим участником.
4. Изучите [TERMINOLOGY.md](TERMINOLOGY.md) — используйте принятые термины.

---

## 4. Соглашения об именовании

### Файлы глав

```
book/NN-Part-X/NN-Chapter-Title.md
```

Примеры:

- `book/00-FrontMatter/00-Preface.md`
- `book/01-Part-I/01-What-is-Vibe-Coding.md`
- `book/02-Part-II/09-Prompt-Engineering.md`

Правила:

- префикс `NN` — порядковый номер главы (две цифры);
- `Part-X` — номер части книги (римские или арабские, как в OUTLINE);
- `Chapter-Title` — краткое название на английском через дефис.

### Другие материалы

- Шаблоны — `templates/`
- Чек-листы — `checklists/`
- Диаграммы — `diagrams/` (когда каталог будет создан)

## 5. Процесс написания главы

### Шаг 1. Подготовка

- Откройте [BOOK_OUTLINE.md](BOOK_OUTLINE.md) и найдите описание главы.
- Создайте файл по шаблону [templates/chapter.template.md](../templates/chapter.template.md).
- Определите связанные главы для перекрёстных ссылок.

### Шаг 2. Черновик

Напишите черновик, следуя структуре из [STYLE_GUIDE.md](STYLE_GUIDE.md):

1. Цель главы
2. Зачем это важно
3. Проблема
4. Основная теория
5. Практический пример
6. Работа с ИИ
7. Типичные ошибки
8. Лучшие практики
9. Чек-лист
10. Итоги
11. Что изучить дальше

### Шаг 3. Самопроверка

Пройдите чек-лист (раздел 7).

### Шаг 4. Редактура

Technical Editor проверяет:

- соответствие STYLE_GUIDE;
- единство терминологии;
- отсутствие противоречий с другими главами;
- наличие практических примеров;
- корректность перекрёстных ссылок.

### Шаг 5. Финализация

- Обновите [PROJECT_STATE.md](PROJECT_STATE.md).
- Добавьте запись в [CHANGELOG.md](CHANGELOG.md).
- При добавлении новых терминов — обновите [TERMINOLOGY.md](TERMINOLOGY.md).

## 6. Правила редактуры

### Обязательно

- Объяснять, а не только определять.
- Каждая концепция — с примером.
- Код — минимальный, читаемый, с пояснением.
- Ссылки на связанные главы.
- Единая терминология из TERMINOLOGY.md.

### Запрещено

- Маркетинговые формулировки и кликбейт.
- Необоснованные обещания возможностей ИИ.
- Смена терминов без обновления TERMINOLOGY.md.
- Дублирование материала из других глав.
- Большие фрагменты кода без пояснения.
- Привязка к одному инструменту или модели.

### Тон

Спокойный, профессиональный, инженерный. Обращение на «вы».

Подробнее: [STYLE_GUIDE.md](STYLE_GUIDE.md), разделы 3–4.

## 7. Чек-лист перед завершением главы

- [ ] Цель главы сформулирована в начале
- [ ] Описана проблема, которую решает глава
- [ ] Теория объяснена с примерами
- [ ] Есть практический пример (реальный сценарий)
- [ ] Есть раздел «Работа с ИИ»
- [ ] Перечислены типичные ошибки
- [ ] Есть чек-лист для читателя
- [ ] Есть итоги и «Что изучить дальше»
- [ ] Добавлены ссылки на связанные главы
- [ ] Терминология соответствует TERMINOLOGY.md
- [ ] Стиль соответствует STYLE_GUIDE.md
- [ ] Нет противоречий с другими главами
- [ ] Объём: 3 000–8 000 слов (или обоснованное отклонение)

---

## 8. Работа с терминологией

- Новый термин вводится один раз с определением.
- Если термин добавляется в книгу — занесите его в [TERMINOLOGY.md](TERMINOLOGY.md).
- Для читательского глоссария — также обновите [GLOSSARY.md](GLOSSARY.md).
- Не используйте синонимы без явного указания.

---

## 9. Работа с кодом и диаграммами

### Код

- До 100 строк на пример.
- Самодостаточный фрагмент, понятный без внешнего контекста.
- Язык программирования выбирается по уместности темы.

### Диаграммы

- Формат по умолчанию: Mermaid.
- Архитектура: C4.
- Каждая диаграмма сопровождается текстовым пояснением.

## 10. Git Workflow

Каждый логически завершённый результат — отдельный коммит.

Формат сообщений:

```
feat(book): add chapter 01
docs(style): refine writing guide
refactor(outline): restructure part II
fix(terminology): align LLM definition
```

Не коммитьте:

- незавершённые черновики без явного согласования;
- временные файлы;
- артефакты сборки (`build/output/`).

---

## 11. Definition of Done

Глава считается завершённой, когда:

- пройден чек-лист (раздел 7);
- проведена редактура;
- обновлены PROJECT_STATE и CHANGELOG;
- нет известных логических ошибок;
- материал понятен без обращения к будущим главам.

---

## 12. Эскалация

Если новый материал противоречит существующему:

1. Зафиксируйте противоречие.
2. Сначала обновите архитектуру знаний (OUTLINE, TERMINOLOGY).
3. Затем обновите затронутые главы.
4. Качество важнее скорости.
