# ADR-0001: Use Markdown and Git as Foundation

**Status:** Accepted  
**Date:** 2026-07-11  
**Deciders:** Project maintainers

---

## Context

Проект «Vibe Coding Bible» — долгосрочная knowledge base: книга, документация, шаблоны, процессы. Необходимо выбрать базовую технологию хранения и совместной работы, которая:

- поддерживает версионирование и прозрачную историю изменений;
- доступна авторам, редакторам и ИИ-агентам без проприетарных инструментов;
- позволяет автоматически генерировать PDF, EPUB, HTML и другие форматы;
- масштабируется на годы разработки без vendor lock-in.

Рассматривались альтернативы: Google Docs / Notion, LaTeX, AsciiDoc, CMS (Hugo, Docusaurus), бинарные форматы (DOCX как primary).

---

## Decision

Использовать **Markdown** (.md) как единый формат контента и **Git** как систему версионирования и совместной работы.

---

## Rationale

### Markdown

| Преимущество | Описание |
|---|---|
| Читаемость | Исходный текст понятен без рендеринга |
| Универсальность | Поддержка в IDE, GitHub, Cursor, большинстве ИИ-инструментов |
| Простота | Низкий порог входа для авторов и редакторов |
| Конвертируемость | Pandoc и аналоги генерируют PDF, EPUB, DOCX, HTML |
| Diff-friendly | Изменения видны построчно в Git |
| Структурируемость | Заголовки, списки, таблицы, code blocks, Mermaid |

### Git

| Преимущество | Описание |
|---|---|
| История | Полный audit trail каждого изменения |
| Ветвление | Параллельная работа авторов и ECR |
| CI/CD | Автоматическая сборка через `.github/workflows/` |
| Распределённость | Локальная работа, offline-first |
| Экосистема | PR, review, issues, интеграции |
| AI-native | ИИ-агенты natively работают с текстовыми файлами в репозитории |

---

## Consequences

### Positive

- Любой участник может редактировать материалы в любом редакторе.
- ИИ-агенты читают и генерируют Markdown без дополнительных адаптеров.
- Сборка артефактов — детерминированный pipeline из текстовых источников.
- ADR, ECR, главы книги — единый формат, единые инструменты.

### Negative

- Markdown не имеет строгой схемы — качество структуры зависит от дисциплины (STYLE_GUIDE, шаблоны).
- Сложная вёрстка (колонки, точный print layout) требует post-processing при сборке.
- Нет WYSIWYG «из коробки» — часть авторов предпочтёт визуальные редакторы.

### Mitigations

- Шаблоны в `templates/` и `framework/templates/` задают структуру.
- [STYLE_GUIDE.md](../STYLE_GUIDE.md) и [EDITOR_GUIDE.md](../EDITOR_GUIDE.md) фиксируют правила.
- [docs/ARCHITECTURE.md](../ARCHITECTURE.md) описывает роли каталогов.
- Сборка через `scripts/build.sh` абстрагирует конвертацию.

---

## Alternatives Considered

| Альтернатива | Почему отклонена |
|---|---|
| Google Docs / Notion | Vendor lock-in, слабый diff, сложная автоматизация для ИИ |
| LaTeX | Высокий порог входа, плохая интеграция с ИИ-агентами |
| AsciiDoc | Мощнее Markdown, но меньше экосистема и поддержка в IDE/AI |
| CMS (Hugo, etc.) | Дополнительный слой; Markdown+Git достаточно для текущей фазы |
| DOCX как primary | Бинарный формат, неудобен для diff и автоматизации |
