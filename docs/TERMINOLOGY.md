Version: 0.2.0

## 1. Назначение

Единый словарь терминов проекта **Vibe Coding Bible**.

Все главы, документы и материалы обязаны использовать термины из этого документа.

Для читательского глоссария см. [GLOSSARY.md](GLOSSARY.md).

---

## 2. Правила использования

- Термин вводится один раз с определением.
- Далее используется последовательно, без синонимов.
- Новые термины добавляются сюда перед использованием в главах.
- Английские термины сохраняются в оригинале, если устоявшийся перевод отсутствует или вводит путаницу.

## 3. Основные термины

### Vibe Coding

Подход к разработке программного обеспечения, при котором инженер работает совместно с LLM, сохраняя контроль над архитектурой, качеством и принятием решений.

Не является заменой инженерных практик. Является их расширением.

### AI-assisted Development

Разработка программного обеспечения с использованием LLM и связанных инструментов на всех этапах жизненного цикла: от проектирования до сопровождения.

Основной термин проекта. Использовать вместо «AI-разработка», «разработка с ИИ» (допустимо в тексте для читателя, но в заголовках и определениях — AI-assisted Development).

### LLM (Large Language Model)

Большая языковая модель. Основной инструмент AI-assisted Development.

Не использовать «нейросеть» или «ИИ-модель» без уточнения, если речь именно о LLM.

### Контекст (Context)

Информация, передаваемая LLM для выполнения задачи: промпт, история диалога, файлы проекта, документация, правила.

Ключевой ресурс AI-assisted Development. Качество результата напрямую зависит от качества контекста.

### Промпт (Prompt)

Текстовая инструкция, передаваемая LLM. Включает задачу, ограничения, формат ответа и контекст.

### Prompt Engineering

Проектирование промптов для получения предсказуемых и качественных результатов от LLM.

### Контекстное окно (Context Window)

Максимальный объём текста, который LLM может обработать за один запрос.

### Chain of Thought (CoT)

Техника, при которой LLM пошагово рассуждает перед выдачей ответа.

### Reflection

Техника, при которой LLM проверяет и улучшает собственный ответ.

### Memory

Механизм сохранения информации между сессиями работы с LLM.

### Tool Calling

Способность LLM вызывать внешние инструменты (API, файловую систему, терминал) для выполнения задач.

### MCP (Model Context Protocol)

Протокол стандартизированного подключения внешних инструментов и источников данных к LLM.

### AI Agent

Автономная система на базе LLM, способная выполнять многошаговые задачи с использованием инструментов.

### Multi-Agent System

Архитектура, в которой несколько AI Agent взаимодействуют для решения сложных задач.

### Guardrails

Ограничения и правила, определяющие допустимое поведение LLM и AI Agent.

## 4. Инженерные термины

### Архитектура (Architecture)

Структура программной системы: компоненты, их взаимодействие и принципы организации.

### Требования (Requirements)

Формализованное описание того, что система должна делать.

### PRD (Product Requirements Document)

Документ с описанием требований к продукту.

### ADR (Architecture Decision Record)

Документ, фиксирующий архитектурное решение и обоснование выбора.

### RFC (Request for Comments)

Документ для обсуждения и согласования технического предложения.

### User Story

Формулировка требования с точки зрения пользователя.

### Domain Modeling

Процесс выделения и описания предметной области системы.

### Event Storming

Метод совместного моделирования бизнес-процессов через события.

### DDD (Domain-Driven Design)

Подход к проектированию ПО, ориентированный на предметную область.

### C4 Model

Метод документирования архитектуры на четырёх уровнях: Context, Container, Component, Code.

### Итерация (Iteration)

Один цикл работы: планирование → реализация → проверка → обратная связь.

### Инженерное решение (Engineering Decision)

Обоснованный выбор между альтернативами с учётом ограничений, рисков и контекста.

### Рабочий процесс (Workflow)

Последовательность шагов для выполнения повторяемой задачи.

### Технический долг (Technical Debt)

Накопленные упрощения и компромиссы, требующие будущих затрат на исправление.

## 5. Термины AI-first разработки

### AI Workflow

Рабочий процесс, в котором LLM участвует на каждом этапе разработки.

### AI Pair Programming

Совместная работа разработчика и LLM над кодом в реальном времени.

### AI Code Review

Использование LLM для анализа качества, безопасности и соответствия стандартам кода.

### AI-first Development

Подход к разработке, при котором LLM интегрирован в процесс с самого начала проекта, а не добавлен постфактум.

## 6. Запрещённые формулировки

| Не использовать | Использовать вместо |
|---|---|
| магия | конкретное описание механизма |
| революция | изменение, эволюция, сдвиг |
| идеальный | подходящий, оптимальный для контекста |
| гениальный | эффективный, продуманный |
| супер / невероятный | (убрать, заменить фактом) |
| нейросеть (без уточнения) | LLM |
| AI заменяет разработчика | AI-assisted Development |
