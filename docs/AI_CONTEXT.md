# AI CONTEXT

Version: 0.2.0

Status: Active

---

# 1. Purpose

Этот документ содержит постоянный контекст проекта.

Его задача — обеспечить единое понимание проекта всеми ИИ-инструментами и участниками разработки.

Он должен использоваться как основной источник контекста при начале нового диалога.

---

# 2. Project Identity

Название проекта:

Vibe Coding Bible

Тип проекта:

Knowledge Monorepo

Основной продукт:

Практическая книга по AI-assisted разработке программного обеспечения.

Вторичные продукты:

- сайт;
- PDF;
- EPUB;
- DOCX;
- база знаний;
- курс;
- библиотека шаблонов;
- библиотека промптов.

---

# 3. Core Philosophy

Главная идея проекта:

ИИ не заменяет инженера.

ИИ усиливает инженера.

Разработчик остается человеком, принимающим решения.

ИИ помогает:

- анализировать;
- проектировать;
- писать код;
- искать ошибки;
- генерировать идеи;
- создавать документацию;
- ускорять работу.

Ответственность всегда остается за человеком.

---

# 4. Writing Philosophy

Книга должна объяснять.

Не рекламировать.

Не восхищаться ИИ.

Не демонизировать ИИ.

Каждая идея должна быть проверяема на практике.

---

# 5. Tone of Voice

Тон книги:

- спокойный;
- профессиональный;
- инженерный;
- уважительный;
- без маркетинговых лозунгов;
- без искусственного пафоса;
- без разговорного сленга;
- без "магии";
- без необоснованных обещаний.

---

# 6. Style Principles

Предпочтение отдается:

- ясности;
- последовательности;
- практической ценности;
- объяснениям;
- реальным примерам.

Следует избегать:

- воды;
- повторов;
- эмоциональных преувеличений;
- модных терминов без объяснения;
- сложных формулировок без необходимости.

---

# 7. Audience

Книга ориентирована на:

- начинающих разработчиков;
- опытных разработчиков;
- технических лидов;
- архитекторов;
- основателей продуктов;
- преподавателей;
- студентов.

Материал должен быть полезен каждому уровню.

# 13. Editorial Rules

При написании необходимо:

не повторять уже объясненные идеи;

не менять терминологию без причины;

сохранять единый стиль;

поддерживать связь между главами;

добавлять ссылки на связанные разделы.

---

# 14. AI Collaboration Rules

ИИ используется для:

генерации идей;

редактуры;

поиска альтернатив;

проверки структуры;

создания примеров;

генерации диаграмм;

поиска слабых мест текста.

ИИ не является источником истины.

Все технические утверждения требуют проверки человеком.

---

# 15. Project Memory

В новых диалогах сначала необходимо ознакомиться с:

PROJECT_STATE.md

BOOK_OUTLINE.md

PROJECT_MANIFEST.md

AI_CONTEXT.md

Только после этого продолжается работа.

---

# 16. Long-Term Goal

Создать наиболее полное и практически полезное руководство по AI-assisted разработке на русском языке.

Книга должна оставаться актуальной в течение многих лет благодаря независимости от конкретных моделей и сервисов.

---

# 17. Non-Goals

Проект не ставит целью:

рекламу отдельных компаний;

сравнение моделей ради рейтингов;

обучение конкретному языку программирования;

копирование документации производителей ИИ.

---

# 18. Continuous Improvement

Любая новая глава должна делать книгу лучше.

Если новый материал противоречит существующему, сначала обновляется архитектура знаний, затем добавляется новый текст.

Качество всегда важнее скорости написания.
